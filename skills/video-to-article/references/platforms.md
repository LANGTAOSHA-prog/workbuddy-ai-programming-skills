# 各平台短视频内容抓取策略

## 可行性总览

| 平台 | 文案可读性 | 字幕 | 推荐做法 |
|------|-----------|------|----------|
| YouTube | 高 | 有(transcript 面板) | 最友好,标题/简介/字幕齐全,优先走浏览器抓取 |
| B站 | 中 | 有(CC 字幕) | 简介 + 字幕较易提取,web-access 可加载 |
| 小红书 | 中 | 图文多 | 笔记正文即文案,图文混排,适合抽取文字 |
| 抖音 | 低 | 难 | 强反爬 + JS 渲染,通常只能拿标题,建议让用户粘贴文案 |
| 快手 | 低 | 难 | 同抖音 |
| 视频号 | 低 | 难 | 微信内封闭,基本需用户粘贴文案 |

## 抓取要点

### YouTube
- 标题、频道、简介、字幕(transcript)基本都可被浏览器渲染后读取
- 提示词:「打开视频,提取标题、简介、以及 Show transcript 里的完整字幕文本」

### B站
- 简介区常有大纲,CC 字幕可被加载后读取
- 提示词:「打开视频,提取简介、分P标题、以及字幕文本」

### 小红书
- 笔记正文本身即文案,图文混排;视频笔记的文案在正文
- 提示词:「提取这篇笔记的正文全文,保留分段」

### 抖音 / 快手 / 视频号
- 强反爬,WebFetch 与浏览器常只能拿到标题与少量简介
- 不要硬编:抓取为空时直接提示用户「把视频文案复制发我,或导出 .srt 字幕,我照样改写」

## 回退原则(硬性)

1. 任一平台抓不到正文 / 字幕,**立即提示用户提供文案或字幕文件**,绝不凭空生成视频内容。
2. 用户给的 .srt / .vtt:跳过序号行与时间码,只取对话文本拼接。
3. 用户给纯文本:直接作为改写素材,无需再抓取。

## 为什么默认不绑 ASR

当前受管环境未预装 ffmpeg / whisper,也无 ASR 类 API key。本地视频"音频转文字"
需要补这两样才能跑。因此主路径设计为「浏览器抓文案/字幕 + 用户直接给文案」,
ASR 仅作为可选增强写在 SKILL.md 的「高级」章节,由用户自行配置后启用。
